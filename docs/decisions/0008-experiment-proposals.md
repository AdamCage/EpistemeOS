# ADR 0008: предложение эксперимента из замороженного набора объяснений

Дата: 24 сентября 2026. Статус: реализованный локальный срез M3; целевые проверки, полный набор 406 тестов и один реальный model call прошли, CI для этого коммита ещё ожидается. Полный автономный цикл остаётся [в плане](../mvp-plan.md).

## Решение

После [предложения гипотез](0007-model-proposals.md) введён отдельный versioned task `experiment_proposal`. Его вход — актуальные `ResearchQuestion`, упорядоченный `ExplanationSet`, связанное дерево `Search`, ограничение числа model calls и host-owned рецепт синтетического эксперимента. Его выход — **одно предложение проверочного шага или abstention**, а не экспериментальный результат. Prompt, структурная output schema и semantic validator имеют новую неизменяемую версию `experiment-proposal-v1`; исторический контракт `hypothesis_proposal` не меняется.

Модель выбирает только разрешённые параметры рецепта `synthetic_causal_v1`: число синтетических единиц, randomized/observational assignment и difference-in-means/adjusted-OLS analysis. Она указывает действие дерева (`baseline`, `discriminate`, `ablate`, `robustness`), ожидаемое наблюдение для **каждой** frozen hypothesis в исходном порядке, различающий контраст, rationale, ограничения и bounded score components. Предсказания должны различаться хотя бы для двух объяснений. Этот синтаксический критерий не доказывает, что тест действительно различает механизмы. Model-supplied оценки не являются вероятностями истинности, evidence или scientific verdict.

Ответ ограничен режимом `exploratory`. Модель не задаёт actor, IDs, команду runner, код, исходные данные, фактический мир, seeds, environment, digest, run limit или собственное одобрение. Признак `proposed` означает прохождение проверки формы и ссылок; `abstained` сохраняет причину и не создаёт протокол. Неизвестные поля, duplicate JSON keys, nonfinite numbers, нарушения диапазонов, неправильный порядок или неполное покрытие hypotheses блокируют применение с сохранением исходных bytes ответа.

## Замороженный вход и переход

Request сохраняет hashes вопроса, ExplanationSet, tree и budget, digest recipe binding, а также prompt/schema/context, provider descriptor, execution specification и actor assignment в append-only событиях и CAS. Context даёт модели каталог параметров и историю планирования, включая предков и исключённых конкурентов. Числовые значения синтетического `world` находятся в host-owned binding, а не в модельном context. Это ограничение передаваемого context, **не гарантия секретности**: текущий локальный provider process не имеет файлового или сетевого sandbox.

Host-owned binding фиксирует рецепт, world, seeds и environment. Context не передаёт числовые значения world, raw outputs или oracle; metadata дерева может содержать исходы прежних шагов. На `agent_dispatch` и снова в сохраняемой транзакции application проверяются актуальные heads вопроса/набора, совместимость дерева и binding, actor, бюджет и ответ. После внешнего вызова устаревший ответ остаётся provenance, но не получает права изменить новое состояние. `agent_response` хранит errors и usage даже при `invalid`/`failed`; `unknown` требует reconciliation по исходному dispatch, а не повторного model call. Это та же граница one-shot transport, что в ADR 0007.

Контекст связывает модель с hash-ревизиями runs/results/claims/reviews уже связанных с деревом protocols: новое evidence до terminal transition также делает ответ устаревшим. Для деревьев, созданных через CommandService, проверяется исходный study в квитанции; ранее занятые деревья дополнительно проверяются по planning-bound protocols и requests. Binding требует формат локального Python runner и совпадение текущего fingerprint при новом переходе. Финальное JSONL-сообщение модели должно содержать то же валидное предложение, что сохранено в `proposal.json`; несовпадение становится `invalid`, исходные bytes сохраняются.

Успешное применение компилирует модельные параметры **в host-owned адаптере**, затем атомарно сохраняет frozen `Protocol`, root `ExperimentNode` и `agent_application` с одной командной квитанцией. `Protocol` связан со всем исходным ExplanationSet; seed schedule, source/environment/data digests, statistical design и предел попыток выбираются host code. Объявленная стоимость для дерева в первой policy — `2 × число seeds` единиц `enqueued_attempt` для primary и отдельного повторного анализа. Применение ещё не выбирает узел, не резервирует выполнение и не создаёт `Run`, observation, claim или review. Selection и [frozen execution batch](0006-execution-batches.md) остаются отдельными переходами.

Application сохраняет версию compilation manifest и ссылки на точные protocol/node revisions. Исторический replay проверяет сохранённые bytes, hashes, receipts и связи именно той версии; новая версия компилятора не пересчитывает и не переписывает прежнюю preregistration. Graph и review basis проходят через request/response/application к frozen context, включая непринятые альтернативы. Отрицательные результаты, отказы модели и устаревшие предложения сохраняются в истории.

В manifest хранится снимок исходника компилятора; при application проверяется, что файл не изменился после загрузки модуля. Для сравнения двух численных реализаций synthetic adapter задаёт default absolute tolerance `1e-9` (host может задать своё значение). Это инженерный порог согласованности вычислений, а не оценка статистической неопределённости или scientific replication.

## Интерфейс и проверенный объём

Публичная форма ответа — [JSON schema v1](../../schemas/experiment-proposal-v1.schema.json); runtime validator дополнительно сверяет порядок frozen hypotheses и статусные правила. CLI `episteme agent recipe --input recipe.json --root <study-root>` сохраняет host-owned binding в CAS. Файл содержит ровно `world`, `seeds`, `environment` и `replication_tolerance`; команда не создаёт исследовательского события и не вызывает модель. `agent.request_experiment` принимает IDs бюджета, ExplanationSet, дерева и binding плюс assignee/provider. `episteme agent advance <request-id>` использует общий controller: сохраняет dispatch/response и применяет `agent.apply_experiment` только для допустимого ответа. Вызов через `episteme command` и повторная доставка сохраняют versioned receipt semantics.

Локальные целевые тесты проверили strict proposal validation, компиляцию fixture, CLI recipe, atomic application, Graph/CAS closure и восстановление/replay. Они используют synthetic transport. Отдельный реальный вызов `gpt-6-sol` применил одно допустимое предложение; [проверка](../validation.md) фиксирует точные IDs, usage, экспорт и восстановление. Научная оценка выбранного теста не проводилась; CI должен быть записан отдельно по фактическому результату.

## Доменная граница и ограничения

`synthetic_causal_v1` — fixture pack с известным генератором: он даёт runner source, отдельный reanalysis source, data/config blob, primary metric и typed statistical design. Генератор и статистические допущения принадлежат адаптеру, не универсальному Kernel. Первичный и повторный анализ используют одни и те же наблюдения; второй исходный код сам по себе не доказывает независимого авторства или контекста. Повтор того же кода, новый seed, независимо выполненный повторный анализ и `new_data_replication` остаются разными режимами. Синтетическая выборка не даёт эмпирического вывода о внешнем мире.

`scientific_validity` остаётся `not_assessed`. После исполнения потребуются механические gates по фактическим outputs, независимый scientific review и, при замечаниях, отдельный replanning. Ни fixture, ни автоматическая компиляция плана не создают reviewer approval или публикационный результат. Перенос этого перехода на afterlife потребует второго adapter contract и проверки предметных метрик, а не проверки имени домена в ядре.
