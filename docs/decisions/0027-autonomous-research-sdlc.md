# ADR 0027 — исследовательский цикл и локальная эволюция

Дата: 25 ноября 2026. Реализованы локальный исследовательский контур и отдельный канал проверяемых выпусков.

## От обсуждения к исследованию

`episteme research start` принимает текст гипотезы и конфигурацию. Конфигурация ограничивает набор кандидатов, бюджет, источники и провайдера. `discuss` добавляет ответы автора. `run --accept <hash>` проверяет последнюю ревизию обсуждения и начинает работу. Автор определяется доверенным локальным вызовом. Принятые условия исследования сохраняются в неизменяемом контракте. `research worker` можно запускать под внешним локальным супервизором. Он подхватывает уже принятые исследования.

Аналитик формулирует конкурирующие объяснения, критик определяет приоритет контроля, разработчик оценивает пригодность типизированных кандидатов, тестировщик проверяет следующее действие, ревьюер оценивает зафиксированный результат, оркестратор применяет переходы. Каждый сеанс модели получает явно собранный контекст. Система сохраняет намерение запроса, хеши данных контекста, ответ и его проверку. При неизвестном результате модели `run` ищет первоначальный результат в рабочем каталоге. Повторную отправку этот путь не разрешает. Для литературы сохраняются намерение, снимок или неудача. Поиск Crossref возвращает библиографические метаданные. Снимок открытого текста даёт локатор, но чтение снимка само по себе оставляет научную новизну непроверенной.

Эксперименты выбираются из заранее разрешённых рецептов посредством `Search`. Протокол компилируется и регистрируется до расстановки исполнителей. Резерв покрывает полный roster. `stage.run` по-прежнему отвечает за один замороженный вычислительный stage. После stage машинный ревьюер может запросить следующий контроль. Заключение привязано к хешу основания claim. Если следующий эксперимент изменил это основание, цикл запрашивает новое заключение до завершения. Старый ответ остаётся в журнале. Машинные ответы сохраняются как `research_step`; допуск научных approvals по `review.submit` остаётся отдельным.

`research export` формирует локальную рукопись, досье на утверждения, связанные события и квитанции, CAS-артефакты и манифест SHA-256. Внутренняя рукопись допускает частичный и неопределённый результат. При наличии допущенных утверждений используется `paper.build`. Цикл разделяет исполнение, механические условия, результат анализа и `scientific_validity`.

## Локальные выпуски

`episteme evolution` ведёт отдельный журнал. Новое исследование может закрепить активную версию через `research start --release-root`. Исследования отправляют проверенные сигналы только своей версии. Два разных свидетельства с одинаковой группой запускают ограниченную кампанию GEPA под `evolution worker`, если для версии зафиксирована конфигурация. Оптимизатор выбирает инструкцию среди разрешённых вариантов по раздельным development-наборам. Закрытый набор остаётся у службы допуска. Кандидаты кода передаются из отдельного worktree. Закреплённый локальный образ запускает кандидата без сети, с read-only root и лимитами процессов, памяти и CPU. Код кандидата видит проекцию приоритетов и предлагает новые значения в пределах той же схемы. Записи научного ядра выполняются хостом.

Активация требует парной оценки, отсутствия критических нарушений и регрессий корректности, а также измеримого улучшения. Проверка здоровья активной версии может автоматически вернуть её родителя. Уже принятый контракт сохраняет свою версию. Сигнал и откат не изменяют научную историю. Базовый контейнерный worker исполняет интерфейс исследовательской политики. Для оценки эффективности текстовой инструкции на модели требуется собственный фиксированный worker с соответствующими задачами.

## Границы первой реализации

- Конфигурации используют зарегистрированные domain packs с локальным профилем v1. Система автономно выбирает допустимый рецепт и может провести ещё один stage, когда для него есть данные, бюджет и допустимый дизайн.
- Повторный анализ в используемых пакетах работает на тех же данных. Режимы new-data replication и independent reanalysis учитываются как отсутствующие, если для них нет установленного происхождения и изоляции.
- Тексты и агрегаты для модели выбираются по контексту роли. Holdout не включается в контекст до регистрации протокола. Локальные исполнения идут под общим пользователем ОС. Это ограничение важно для оценки физической недоступности файлов, включая публичный holdout.
- Автоактивация кода применяется к локальному контейнерному пакету исследовательской политики. Для защищённого ядра, допуска и внешней отправки действуют отдельные полномочия.
- Пилот на публичных данных проверяет работоспособность контура и ограничение вывода. Научную результативность оценивает отдельное парное исследование.
