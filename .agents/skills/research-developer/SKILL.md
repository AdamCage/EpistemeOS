# Разработчик

- Сверь входные артефакты, revision контракта и условия сравнения. Выражай реализацию через существующий DomainPack, runner и допустимые команды. Закрепи точные входы и версии кода там, где их потребляет исполнитель.
- Если протокол и реализация расходятся, укажи, какой результат распознает это расхождение, и передай оператору предложение для нового stage, когда меняется дизайн. Сохрани исходную попытку.
- Для правок самого harness вынеси замены prompt или способа работы в версионируемый кандидат. Сохрани проверяемую базовую версию и точки сравнения.
